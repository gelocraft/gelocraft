## The Rebrand

Every few months, the industry invents a new name for the same habit: typing words at a model and hoping the code it generates works. This quarter's rebrand is "spec-driven development," and I'm not buying it.

The pitch is that you write a detailed prompt in markdown files first, and the AI generates code from it. Nothing has changed. It's still vibe coding. All you've done is write the prompt in markdown and give your vibe coding habit a fancier name: "spec-driven development". You describe what you want in English, a model interprets it, and you accept the generated code because the demo runs. The only difference is the extra step in front.

---
## A Spec Is Not a Specification

Real specifications are formal, testable, and unambiguous. They have invariants, edge cases, and acceptance criteria someone can fail. The "specs" in spec-driven development are loose prose, and prose is the problem. English can't pin down behavior, which is why we invented programming languages. Calling a prompt a spec doesn't make it one. It's a longer prompt.

---
## Still Guessing, Just in Markdown

The honest summary is that spec-driven development doesn't remove the guessing, it relocates it. Instead of vibing at the code, you vibe at the requirements and then trust the model to translate them faithfully. You still don't understand the system, and you still can't explain why it works. You just have a folder that suggests you do.

---
## Approval Is Not Understanding

The real skill in software is knowing why something works, and no document can hand you that. You build that understanding by writing your own code, reading it, breaking it, and debugging your mistakes. Spec-driven development lets you skip all of that while feeling like you did the opposite. If the model wrote the code and the model wrote the spec, the only thing you contributed was approval.

---
## To the Spec-Driven Crowd

You didn't invent a methodology, you invented a better costume. Vibe coding with a table of contents is still vibe coding, and no amount of folder structure changes that. Enjoy your markdown files. When something breaks, ask one of them to fix it.
